# SC-01 — Scam Pattern proposal

Planning contract · 2026-10-08. No new runtime support, registration or release is asserted.

**Decision gate:** Owner/RFC acceptance of this proposal before registration or runtime issuance.

## Baseline job and outcome

Research whether contextual fraud indicators support a useful, bounded possible-scam finding.

The reader can inspect each validated indicator and dismiss a warning without an accusation of intent.

## Inputs, outputs and boundaries

**Inputs:** Content and contextual evidence.

**Outputs:** A proposed possible-scam warning exposing each validated contextual indicator, limits and a one-action dismissal.

**Limits:** Weak indicators may share one cause; News, quotations, and legitimate requests can contain the same terms; Recall tradeoffs must publish false positives and allow dismissal

## Method and evidence development

- Define pressure, value transfer, identity assertion and channel-switch labeling with benign controls.
- Measure individual indicators and combinations, including shared causes and use/mention.
- Validate audience-specific error costs before accepting a recall-weighted policy.

## Acceptance and error boundaries

- Two-family co-occurrence is a hypothesis, not independent corroboration.
- Publish measured false-positive rates and category misses; hedged wording and one-action dismissal are required.
- If indicator combinations do not separate benign discussion from relevant risk, do not issue the proposed claim.

Numeric thresholds, supported languages/subjects and hardware/latency requirements are defined and accepted for this claim before independent evaluation; no PS threshold is borrowed by default. Existing editorial floors are not measured accuracy.
