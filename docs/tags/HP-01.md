# HP-01 — Hallucination indicators

Planning contract · 2026-10-08. No new runtime support, registration or release is asserted.

## Baseline job and outcome

Identify validated inconsistency and unsupported-specificity indicators without equating them with proven falsehood.

The reader knows which inconsistency or unsupported detail warrants checking and why.

## Inputs, outputs and boundaries

**Inputs:** Content, with references where the method requires them.

**Outputs:** The supported inconsistency/specificity indicator, its relevant spans and uncertainty; no blanket falsehood verdict.

**Limits:** Dates, precise writing, repetition, or missing hedges do not establish hallucination; Cannot be emitted by the current runtime; Independent labels are missing

## Method and evidence development

- Evaluate specificity, contradiction, repetition and hedging independently.
- Define when indicators can be combined; track shared causes instead of counting them as independent votes.
- Test satire, creative work, repetition, uncertain language and consistent unsupported statements.

## Acceptance and error boundaries

- Independent labels and comparison with simpler baselines establish useful indicator performance.
- The release claim names the supported indicator; it does not infer model intent.
- No source lookup capability is misrepresented as a factual verification.

Numeric thresholds, supported languages/subjects and hardware/latency requirements are defined and accepted for this claim before independent evaluation; no PS threshold is borrowed by default. Existing editorial floors are not measured accuracy.
