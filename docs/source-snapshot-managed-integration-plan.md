## Existing gap and intended outcome

The current artifact adapter enumerates committed source but does not bind a
received source archive to those Git bytes. Its route is blocked. The current
copy-profile inventory also predates the protected source. A user must be able
to authenticate an exact bounded source snapshot, retain its applicable notices,
and exercise an explicitly supported source entry point without trusting a
received packet's claim that it is approved.

## Architecture before implementation

1. Integrate the separately reviewed current copy classifier and its immutable
   predecessors. Its finite third-party/grant identities and explicitly named
   project additions stay closed. No directory-wide or suffix-wide grants.
2. Add a trusted-source adapter for the `source-snapshot` dependency route. It
   requires the exact selected route/component shape, current file identities,
   and the actual copy classifier. Unknown or changed grants remain blocked.
   Only source copying is admitted; bundled runtime/platform/model rights are
   separate. Other routes cannot inherit this permission.
3. Extend the existing artifact adapter, rather than adding an endpoint. Before
   format verification, compare the complete canonical archive to the caller's
   trusted Git commit using the existing supervised streaming binding. Require
   the same commit, bytes and archive digest across graph, policy and artifact.
   Retain current resource caps and fixed refusal output.
4. Add a managed source consumer with held no-follow private staging. Capture
   inputs once, authenticate the actual protected-main Sigstore statement and
   current copy policy, then materialize only the finite standalone PS source
   entry-point cohort from the authenticated archive. Execute isolated positive,
   negative and refusal probes; no package install, network or arbitrary archive
   command. The full source archive is preserved for inspection, with the probe's
   limited scope explicit. No other tag is required for this PS source probe.
5. Add a protected-main producer to the existing artifact workflow. Build the
   actual canonical snapshot, derive its SPDX evidence, sign with the existing
   fixed workflow identity, independently verify, and execute that managed
   consumer before offering the bytes. PRs only execute source/failure controls;
   a branch run cannot sign an admitted release.
6. Freeze integration sources, obtain a distinct review, and run affected checks
   before the ordinary protected publication flow. Record actual production
   evidence separately from local or injected-signature controls. Refresh global
   source-bound selections only after the image and release changes freeze.

## Risks and limits

- Archive self-description is not authenticity: trusted Git and protected signer
  identity must agree. No execution before both copy permission and authenticity.
- A new file is not automatically covered by an old inventory. Every current
  source addition needs an explicit classification; SDK/model acquisition is not
  authorized by source-copy admission.
- The existing 64 MB compressed /256 MB expanded source bounds, 16,384 files,
  per-file bounds, 60-second binding and 16 MB packet cap remain. Measure actual
  size; refuse rather than silently raise a limit.
- Mutable files, hardlinks, symlinks, replaced parents, malformed input, wrong
  commit, unknown notices, untrusted signer and failed probes return Unavailable.
  Failed private stages are retained when safe cleanup cannot be established.
- Source authenticity and license notices do not establish detector accuracy,
  legal clearance, a complete compiled graph, or all fourteen route obligations.
  F-057/X-02 remain open until their entire preserved contracts work.
