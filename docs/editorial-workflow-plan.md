# Editorial workflow implementation plan

Architecture before implementation: an owner-private offline newsroom review workflow imports an existing current unsigned text assertion and the owner-selected already-evaluated subject. Bind its exact assertion bytes, frozen-normalized subject identity and reviewer selection; reject historical/different preprocessing or detector identities, bad schema, changed input, unsupported asserted codes and out-of-range evidence. Never run a detector, infer independent accuracy, authenticate a reporter, or convert an editor's choice into a public tag. Short console output; a new owner-private folder stores a bounded journal and a self-contained accessible HTML view. Subject text is included only with a separate explicit choice, with privacy limits explained. Known tag codes remain small and expandable. No upload, account, endpoint, external font or script. Optional supersession binds the complete prior private journal, preserves source assertion identity and retains correction lineage. Test installation/use/removal against Mac and isolated Linux, actual browser readability/keyboard/XSS/private boundaries, source/correction/unsupported failures, and unaffected personal results. Full F-157 closure must follow its preserved acceptance; partial integration cannot be relabeled complete merely to reduce the count.
Before broadening the importer: support the site's actual detailed on-device preview export separately from the current unsigned gateway wire record. The summary deliberately lacks subject identity and cannot support a bound editorial review; refuse it rather than invent identity. Browser exports must retain their exact preview/candidate/unreviewed/training-null/redaction-false semantics and match the current projected bundle, runtime, normalization and method identities. No browser candidate becomes an asserted wire tag. Preserve source format and source bytes/digest, show the editor choice separately, and test an actual browser-produced export through import, correction, static HTML and removal. A claimed source match does not authenticate its producer or independently validate it.

Selected supported route: owner-held Linux/macOS CLI plus its offline static review view, importing the current detailed web preview export or current unsigned gateway wire record. Install uses the existing hash-locked Python environment; use produces a separate private editor decision and correction; removal deletes only explicitly owned private outputs. Full newsroom CMS, vendor watermark or identity integrations are separate retained scope records. This route does not depend on or certify another integration.

Risks: unsigned imports can be forged; declared editor identity is unauthenticated; source matching proves identity consistency, not execution; hashes and spans can correlate private content; stale method versions must be refused; optional HTML text inclusion can expose private information; output cannot become a training label or tag release approval. Enforce bounded closed formats, current method identity, private descriptor-bound files, exact correction binding, no network/evaluation, HTML escaping and restrictive CSP. Keep source decisions and source findings visibly separate.

Importer correction before changing its format contract: the actual handheld UI adds a local UUID `record_id` after the worker returns. The first importer recognized the worker shape but refused the full real export. Require and preserve that UUID as a declared source identifier, while retaining all preview/unreviewed flags and unauthenticated status. Its presence does not establish a signed wire assertion. Update the practice producer and synthetic controls to include the same UI field; retain the failed actual-export receipt.

Before the fixture repair: the full suite found that `tests/test_local_cli.py` assigns the live evaluator's `MODELS` list to a test row, then corrupts its fingerprint in a stale-record test. Subsequent actual gateway fixtures inherit that corruption. Copy the test metadata before mutating it and add a regression that demonstrates the shared producer metadata remains unchanged. This is a test-isolation repair, not a changed detector or relaxed importer. Refresh the current route review only after current source-bound checks; retain its stale-inventory refusal.
