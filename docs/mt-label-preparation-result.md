# MT annotation preparation · engineering result

A complete private offline preparation workflow now runs: create two blank forms,
validate each supplied response, then compute four separate agreement reports and
a private review queue. The [candidate guide](mt-annotation-guide.md) addresses
pressure versus legitimate urgency/persuasion, constrained choice and feasible
alternatives, authority attribution, and use versus quotation/mention. The
[usage guide](mt-label-preparation.md) gives the working commands.

This delivers candidate guide/preparation software for TAG-MT-A01 and supports
future T-MT/F-019a/b/c/F-056 work. It does not claim accepted taxonomy, real human
labels, independent validation, adjudicated ground truth or full original closure.
No model predictions, detector calls, restricted corpus, network, SDK install,
telemetry, endpoint, browser build or live policy change was involved.

Evidence is deliberately separated:

- 19 initial focused engineering checks passed before peer correction.
- An actual tiny peer counter found that a held private ancestor could acquire a
  `.git` marker without changing inode/mode. The old result was retained.
- Four affected correction controls passed: late prepublication Git refusal,
  postpublication OutputUncertain, reserved Git destination refusal/normal output,
  and unexpected packet-member refusal. No full23 execution was claimed at that
  stage. Subsequently a fresh full23 focused suite passed on unchanged corrected
  source, recorded separately in `runs/2026-11-22-mt-label-full23-current-controls.json`.
- The final source-stable actual CLI exercise passed11 commands using six authored
  examples and **two synthetic response files, zero human raters**. It exercised
  preparation, both validations, agreement, no-overwrite, incomplete answers,
  altered form, raw/NFC-equivalent source edit refusal, private permission refusal,
  recovery and constant unknowns. Temporary private files were removed.

The final CLI receipt is
`runs/2026-11-22-mt-label-git-corrected-cli.json`; the source-stable affected-control
receipt is `runs/2026-11-22-mt-label-git-corrected-controls.json`. Prior candidates,
the original typed bool/int identity counter and the peer Git-marker counter are
preserved. Source byte identity establishes which preparation code ran, not label
truth or professional acceptance. Final result prose is written after execution
and is not relabeled as an execution input.

Both uncertain and insufficient-context answers remain actual nominal categories.
Reports separate their counts from decisive-rating and joint-decisive coverage.
Unanimous constant uncertainty produces Unavailable alpha and zero decisive
coverage, not “perfect” agreement. The existing0.55/candidate_met comparison is
explicitly UNADOPTED; no aggregate MTpass, category-error study or confidence
calibration follows. The review queue remains private and has no auto-adjudicated
answer. Default console output omits text, context, reasons, unit IDs and user
input hashes; even aggregate counts may be sensitive for small cohorts.

The independent human/protocol/sampling/adjudication/calibration/release gates are
unchanged. Existing MT literal methods, JPEG, PS and other tags are untouched and
do not consume this agreement as a release dependency. Root integration, normal
source registration and any protected publication are separate from this isolated
component handoff.
