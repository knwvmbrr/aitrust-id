# Credential-flow method preview architecture

F-012 gains a separately invoked, optional Python-code method preview under the
existing PS modal. The production PS route and its signal mapping stay unchanged.
The PM owns shared mounting and build integration; this branch supplies a Slot
and exact-source builder with an unpublished engineering fixture.

The adapter calls the unchanged canonical `credential_flow.observe` 1.0.2 on at
most 8,000 raw and frozen-NFC Unicode codepoints / 32,000 UTF-8 bytes. A dedicated
fresh Pyodide worker loads the existing pinned public runtime, verifies every
bundled source byte, imports the adapter and accepts source as a function argument.
No submitted program is executed, imported, interpolated into Python or read as a
file path. Caller context declarations are omitted: this standalone profile does
not determine use, mention, recommendation or intent.

The result wraps the entire canonical observation with exact raw/NFC and source
identities. A closed browser validator checks every nested field, false assertion,
span bound/membership and count relation before rendering either result or private
details. Whole-record native/browser parity controls cover supported and refused
programs. Source verification/parity establishes this method identity, not empirical
accuracy or truth. The worker is terminated after each run. Edit, Clear, Cancel,
unmount, timeouts and malformed replies invalidate ownership; lazy import/render
failures stay within this optional surface.

Risks and acceptance: loading Python costs memory and an initial public download;
loading has a 45-second wall bound and observation/validation a six-second bound.
The finite supported syntax can refuse ordinary programs and zero observations is
not safety clearance. Reading a credential-named source feeding an HTTP argument
proves neither runtime execution, actual credentials, consent nor malicious intent.
Results contain private linkable hashes/spans, hidden until explicitly expanded;
no automatic exports, input storage or uploads. Static bundled source/notice files
are read with no-follow held descriptors; source drift before publication preserves
old outputs, and uncertain publication is reported honestly. No new endpoint,
account, dependency or another tag's module is introduced. F-012/full tag acceptance
and the original scope percentages remain unchanged.
