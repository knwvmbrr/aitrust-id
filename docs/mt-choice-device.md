# Look at the two items you choose

Open the [MT modal](https://aitrustid.com/#person/MT), then **Choose two items ·
preview**. This optional on-device method is literal wording practice. It does
not issue an MT tag, judge intent or decide whether another option is feasible.
The full MT validation and human acceptance remain open.

## Try an example

1. Choose an invented example, or paste an English passage. Enter the two exact
   item strings in their order; each must occur once.
2. Add a passage you nominate as context. Confirm that you choose this whole
   passage as the frame and this extra passage as context.
3. Choose **Check selected wording**. Read the short observation. Exact details
   stay closed unless you choose **Show exact selected record**.

Not-only/but-also is additive wording. Either/or, only/or, neither/nor and
between/and are separate finite paired constructions. These same words appear
in menus, lessons, quotations, safety advice and ordinary comparisons. The method
does not resolve quotation/endorsement, negation scope, exhaustiveness, source
support or manipulation. Your extra passage is not authenticated or verified as
an available alternative. An unmatched grammar result means only that this finite
method did not match your declared items; it is not a safety clearance.

## Privacy, limits and errors

No worker or analysis starts before you choose Check. Public UI/manifest files
can load when you open the panel. Check starts a new isolated worker using the
existing pinned on-device Python runtime. Inputs travel as local worker messages,
not network requests. They are not stored in browser storage, automatically
exported, uploaded, enrolled in research or used for training. No account or
model API is involved. Public asset hosting can still see normal request metadata.

Passage and context each have a 2,000 raw/frozen NFC code-point and 8,000 UTF-8-byte
limit; each item has a 256-code-point/1,024-byte limit. The complete JSON request
must fit 24,000 bytes. Complete oversized pastes stay visible and refuse; they are
never clipped into accepted text. Missing, repeated, overlapping, reversed or
otherwise unsupported selections refuse without implying no findings.

The public manifest has its existing 10-second whole-stream deadline. A chosen
worker's startup is bounded to 45 seconds and evaluation/validation to 6 seconds.
Unavailable can mean files, input, worker, deadline or integrity failure; it does
not mean safe or a completed zero result. A failed optional panel does not change
other methods. Close/reopen a manifest-failed panel to retry.

Editing or selecting an example invalidates old results and stops the worker.
Clear removes this panel's fields/results. Cancel stops its pending check.
Closing the panel or modal disposes its worker and draft. These controls do not
clear another method's input. Cleanup describes application state, not forensic
memory erasure. Exact records contain hashes, positions and method metadata that
can reveal or link information despite omitting full input words; inspect them
before sharing. There is no automatic details export.

## Offline availability

On-device computation does not imply that first use works without a connection.
The initial public files need to be available. The website's existing **Save for
offline use** control can retain public `/assets` and `/device` files, including
this method, in its existing explicit allowlist. It never caches inputs or POSTs.
A successful installation and retained browser cache are prerequisites; browsers
can evict files. If files are missing while offline, this preview says
Unavailable. Offline browser/engine execution must be demonstrated by the current
integration proof before claiming support; physical-phone operation is separate.

Remove offline files with the existing removal control. No additional service
worker permission, daemon, server endpoint or network origin is introduced.

## Evidence interpretation

The full record binds raw UTF-8, frozen Unicode15 NFC, ordered unique items,
nominated corpus/context and the exact six source hashes before display. Closed
record/marker/span/count checks and native/browser parity are engineering
consistency checks, not independent methods, source authenticity, signed verdicts
or semantic accuracy. Native and browser runtime metadata differ and are reported
separately in execution comparisons. A compromised page, runtime or OS remains
outside those local consistency guarantees.
