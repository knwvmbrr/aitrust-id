# Agent-output identity: architecture before implementation

F-158 delivers an optional adapter for an explicitly selected, reviewed single-file
Python stdio agent. The caller pins its descriptor, program bytes and Ed25519 key.
The adapter records successful bounded execution and signs a statement binding the
declared agent to the exact returned UTF-8 bytes. A verifier supplies the trusted
descriptor and public key separately. A signature establishes the selected key's
statement and byte integrity, not independent proof of execution, AI generation,
autonomy, a person's identity, benign intent or content truth. No new tag is adopted.

The actual answer stays in an owner-private folder outside every Git checkout.
Private inputs and keys are descriptor-read, bounded, owner-held, unlinked regular
files. Refuse existing destinations before execution. No task, command line, key,
stdout or stderr is copied into logs; the private answer file is deliberate output.
The optional HTML displays answer text only on a separate explicit choice. Hashes
and opaque handles can still correlate information; there is no automatic upload.

Run only a caller-reviewed program after an explicit execution flag. Snapshot that
program into a private temporary directory; never execute inspected answer text.
The selected agent has its OS user's file and network privileges. This adapter is
not a sandbox. Do not forward credential environment variables automatically.
The existing supervisor bounds pipes, execution time and process-group cleanup;
trusted programs can escape a process group and require their own containment.
No local Docker, daemon, HTTP listener, account or endpoint is added.

Reuse existing canonical signed-record crypto rather than inventing a signature
format. Domain-check the agent payload, exact descriptor, current recorder identity,
output bytes and unsupported claims after verifying its detached signature. Keep
revocation and local-clock authenticity explicitly unchecked. Old recorder sources
are unavailable for this current profile rather than silently reinterpreted.

PS is a separately requested, isolated existing checker. Recording does not depend
on PS, redaction, gateway or registry; PS still runs without an agent. A missing,
failed or timed-out checker yields its own Unavailable state while preserving the
completed source record and answer. A source failure never creates a success
receipt. No training data, independent accuracy, BT/FA/PA verdict or certification
is inferred. Keep any optional checker evidence separate from source identity.

Verify actual CLI record/verify and private offline HTML on supported macOS and
clean Linux. Exercise wrong keys/descriptors, tampering, duplicate/extra fields,
source drift, invalid UTF-8, deadlines, output floods, key/environment canaries,
unsafe paths, pre-existing destinations and optional-checker failure. Use a clearly
identified rule-driven practice agent, not a pretended model or human reviewer.
Publish the guide and executable evidence; retain broader institutional, human,
independent tag and integration-package acceptance separately. Close F-158 only
after its complete supported software workflow and required checks are evidenced.
