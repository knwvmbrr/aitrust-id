# Link an editorial correction to a private dispute

Use this offline with invented inputs in the synthetic community workbench. The
bridge connects a wrong-result report to an exact editorial correction. Its
private receipt records which assertion the report challenged and which new
journal superseded the prior editorial decision. The journal retains the original
finding and records the editor's decision alongside it.

Create a private folder outside Git. Follow the [editorial workflow](editorial-workflow.md#record-a-correction)
to produce a correction packet and output. Use `mod-one` or `mod-two` as the
correction reviewer, matching the workbench moderator who will review the report.
Run `editorial-review.py --supersede` without `--include-subject`. Use the exact
prior journal and choose a different decision or reason.

Use the [workbench CLI](community-core.md) to open a synthetic `wrong_result`
report. The report's `target_id` is the original gateway `assertion_id` or detailed
browser `record_id`. Save its report ID. The bridge uses the current detailed PS
browser or gateway wire formats accepted by the editorial workflow.

## Prepare the reference

Set the paths to the files and folders you selected and the ID returned when you
opened the report. In this example, `correction-packet` and `correction` are the
folders generated by the editorial CLI.

```sh
AITRUST_DISPUTE_HOME="/private/owner/practice"
AITRUST_DISPUTE_ID="your-report-uuid"
install -d -m 700 "$AITRUST_DISPUTE_HOME/links"
python3 scripts/link-dispute-correction.py prepare \
  --workbench "$AITRUST_DISPUTE_HOME/community" \
  --registry "$AITRUST_DISPUTE_HOME/links" \
  --report "$AITRUST_DISPUTE_ID" --moderator mod-one \
  --packet "$AITRUST_DISPUTE_HOME/correction-packet" \
  --correction "$AITRUST_DISPUTE_HOME/correction/editorial-review.json" \
  --confirm-synthetic-link
```

Save the returned `replacement_reference_id`. The prepared plan pins the chosen
report, moderator, workbench and artifact bytes. The reference is separate from the
assertion UUID because the correction retains that original assertion ID.

## Record the review and finish the link

Use a fresh request UUID and the reference returned by `prepare`. Pass the
following closed request to the workbench CLI on standard input. Substitute your
report, reference and request UUIDs.

```json
{
  "format": "community-workbench-request/v1",
  "synthetic_only": true,
  "request_id": "55555555-5555-4555-8555-555555555555",
  "operation": "review_report",
  "data": {
    "report_id": "your-report-uuid",
    "disposition": "correction_referenced",
    "replacement_record_id": "the-prepared-reference-uuid"
  }
}
```

```sh
python3 scripts/community-workbench.py apply \
  --root "$AITRUST_DISPUTE_HOME/community" --actor mod-one < "$AITRUST_DISPUTE_HOME/review-request.json"
python3 scripts/link-dispute-correction.py link \
  --workbench "$AITRUST_DISPUTE_HOME/community" \
  --registry "$AITRUST_DISPUTE_HOME/links" \
  --report "$AITRUST_DISPUTE_ID" --moderator mod-one \
  --packet "$AITRUST_DISPUTE_HOME/correction-packet" \
  --correction "$AITRUST_DISPUTE_HOME/correction/editorial-review.json" \
  --confirm-synthetic-link
```

The final `link.json` is in `links/link-<report-id>/`. It records the original
assertion, prior journal and correction digests, report and database identity, and
moderator disposition. Keep the registry private. Hashes and IDs can link files
and activity even though the receipt excludes bodies, tag spans, and file paths.

The bridge checks one selected predecessor in one local registry. It checks that
selected records match the current checkout's method and prior journal. The
moderator and editor labels are local operator selections. Independent human
identity, source authenticity, accuracy, and current public registry status
require separate evidence.

## Handle a refusal

Use the original files and database from preparation. A copied or rebuilt store
has a different identity. The same report must carry the assigned reference,
`correction_referenced` disposition, and the selected moderator. An exact replay
after a completed link refuses and preserves the existing private file. If a plan
or prior journal is lost or damaged, keep the existing records for operator review
before filing a new synthetic case.

Run the [focused lifecycle tests](../tests/test_dispute_correction_link.py) to
exercise normal browser and gateway records, changed versions, private file
permissions, copied workbenches and publication boundaries.
