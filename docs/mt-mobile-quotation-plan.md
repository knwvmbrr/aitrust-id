# Mobile double-quote authority candidate

Predeclared 2026-11-21 · worker Codex / web_camo · T-MT / F-019c.

The existing browser already runs ASCII quotation-aware authority 1.0.0. This increment adds a distinct opt-in candidate because ordinary phone curly double quotes currently refuse. It does not remount or rename the existing method, issue an MT tag, infer endorsement/negation/intent or change original acceptance/percentages.

The candidate accepts one double-quote style per passage: consecutive lexical ASCII pairs, or explicitly balanced U+201C/U+201D pairs. Cross-style, unmatched, backslash-adjacent, guillemet and backtick syntax refuses. Repeated curly openings are detectable nesting and refuse. ASCII pairs do not establish intended nesting; adjacent pairs remain literal separate ranges. Single quotes/apostrophes are ordinary characters. Source-marker association stays in the same literal unit and quotation context.

Reuse the unchanged canonical ASCII scanner on a one-codepoint projection of supported curly delimiters, preserving every source offset. Publish a new method/version/grammar and the original normalized subject identity; never present the projected text as the original. Private details contain no text, but hashes/locations remain linkable.

Use the existing fresh-per-check MT worker/client. Candidate payload and validator load only when its new selection runs, from a separate hash-bound optional bundle (fixed inert manifest metadata is embedded in the shared worker); a refused candidate cannot poison later independent urgency/ASCII runs. Keep legacy Python sources and generated legacy bundle bytes unchanged. Extend the existing hardened builder to prepare the optional bundle without new package hooks. The MT-only UI gains “Include curly quotes · preview” with short placement counts, existing private-details opt-in, keyboard/error/lifecycle behavior and unchanged no-upload/no-storage boundaries.

Owned: new canonical/adapter/CLI/validator/manifest/payload; existing MT client/worker/result structural helper/UI/builder/fixture and focused tests/verifiers; own docs/runs/attributed changelog. PM owns shared catalogue/package/preparation hooks, board, scope/state and publication.

Risks: confusing lexical placement with meaning, ASCII nesting ambiguity, boundary/Unicode offsets, optional import/payload coupling, stale work and resource limits. Verify legacy bytes, canonical native/browser full records, raw/frozen NFC/source binding, malformed evidence, mixed/mismatched syntax, marker locality, combining/non-BMP text, phone reflow, cancellation and recovery in Chromium and WebKit. Keep failed candidates immutable. Distinct review and PM protected integration/publication remain required. Actual engines are not physical phones, human accessibility, independent ground truth or MT release validation.
