## Owned implementation and contract

New files only: `tools/source_release_policy.py`,
`eval/dependencies/source-snapshot-release.json`, this plan, focused tests and
source-bound runs. No shared policy, graph, signing workflow, catalogue, ledger,
source inventory or root checkout changes. No installs, downloads or execution
of any file named by input data. No large source archive is constructed locally.

Build a finite reviewed baseline mapping from the actual committed Git tree.
Each baseline path and Git blob identity is explicitly assigned to its applicable
source category and exact grant/notice evidence. Bind the complete mapping to a
fixed digest inside the new trusted helper: a caller cannot rewrite its grants
and merely recompute adjacent metadata. The helper executes only literal Git
read-only commands under bounded process/output budgets. It never imports a
copied package, executes a source/archive member or fetches a URL.

Review categories before marking the profile eligible: project Apache source and
notice; separately licensed CC specification/SPDX schema; Unicode data and copied
reference modules; exact OFL fonts; authored synthetic fixtures/project artwork;
selected PS source ZIP copies; vendored source and retained source-evidence
texts with their own exact grants/attribution. Container and evidence roles stay
separate from installed runtime/model grants. A copied copyright notice or source
header is not automatically project Apache. Unknown, missing, changed or new
unmapped files, missing notices, inconsistent source grants or unresolved actual
source-offer requirements refuse. No generic allow for unrecognized paths.

The initial supported profile is an exact reviewed tree, not blanket permission
for future commits. New first-party files or changed code also require a new
reviewed profile revision, rather than inheriting an unchecked label. The helper
must be independently usable on a sparse checkout by reading committed objects;
physical present files must agree with their selected committed identity. Report
fixed summary facts only by default, with no arbitrary path/input echo. Method
source and mapping identities are captured around actual execution.

## Safety and resources

Use no shell or caller-selected executable/arguments. Reject replacement refs,
non-regular Git entries and unsupported object shapes. Keep16,384 files,
32,000,000-byte individual blobs and256,000,000-byte declared source total, with
bounded listing/mapping/aggregate inspected term bytes and a finite whole-check
deadline. Sequential term reads do not retain the whole tree in RAM. Process
ownership/cancellation and fixed errors must not affect unrelated checking.
The current disk reserve is below2GiB: only tiny sparse source and private
engineering records are created; no SDK/cache/runtime/archive/build duplication.

## Acceptance and handoff

A full eligible recommendation requires positive complete category review, exact
source/grant bindings, supported checkout execution and actual refusal controls
for unknown/missing/changed files, coherent data rebind, notice drift and resource
limits. The helper remains refused if any concrete source grant cannot be bound;
record that exact file/evidence gap instead of an inherited general slogan.
Distinct reviewer then checks actual source and affected behavior before normal
attributed handoff. Real shared-policy admission, graph integration, protected
main signing and managed consumption remain separately owned work. No authority,
accuracy, professional opinion, or original percentage is created by this plan.

## Implemented use and explicit finite additions

Run `python3 -I -S -B tools/source_release_policy.py` on the trusted source
checkout. Default selection is its actual HEAD. `--source-commit` accepts only an
existing commit object; a tree identifier is refused. Selection does not change
the trusted policy or choose a program. Summary output contains identities/counts
and false authority flags, never source bodies, account details or a caller path.

The current fixed table also explicitly names the13 project-produced run/event
paths added by the PM between3f199 and032671e54bbf6a0466977d7b48e6dfa6fd9c4afc.
This is not a future runs wildcard. The owned helper/data/plan/test, exact two
execution/review receipts, preserved initial fixture-failure receipt and fixed
attribution event path are likewise explicit additions under the project grant.
Public certificates/signatures/timestamps are a separate factual-record class,
not relicensed as project software or treated as actual authority.

Changed project source is inspected by a literal stdlib summary worker. Its Git
child shares the supervisor's process group, reads at most the declared32MB blob
plus one refusal byte, verifies Git content identity, strictly decodes UTF-8 and
returns at most1024 bytes of hashes/types. Source is never evaluated. The
supervisor retains the existing bounded worker/kill/reap contract. Whole check
is30seconds plus that helper's at-most5second failure cleanup; aggregate inspected
project text is64MB. Missing local objects cannot trigger a fetch: read-only Git
runs in an empty environment with lazy fetching disabled and protocols refused.
No new file/count/compressed source-archive capacity is approved by this helper.
