Architecture recorded before implementation on an isolated branch from 69d7a370.
The owned shared files are .github/workflows/ci.yml and eval/revalidation.json.
All prior commands, job authorities, runners, dependency locks and deadlines stay
in place. No native SDK, optional model or acquisition step is added.

The spec job adds the existing current source tests (79 collected cases across
V4, admission, managed consumer, workflow and V3) and a separate four-file command
for web-runtime obligations, whole-web artifact, iOS resource projection and MT
private export. At the integration checkout those counts are 21/26/34/8, or 89;
the isolated 69d base has 25 web cases, or 88. These are collected declarations,
not new successful executions. The site job adds the existing thirteen inert
Node observer controls after its installed Node prerequisite.

Revalidation keeps its prior ordered commands. Append the V4 test to the existing
protocol source command and add one Python pytest command for the four new
software cohorts: protocol 78 to 79 commands. Website retains 66 commands. Add
missing named source, test, documentation and finite retained-data patterns to
protocol and website. PS, PII and extension definitions remain byte-value equal.
The manifest is a common input, so old capability receipts become stale and the
PM must run and assess the final frozen hosted profiles before selection.

The existing command parser admits repository scripts under scripts/ and Python
pytest modules. It does not admit tests/*.mjs directly. Therefore observer controls
are an explicit ordinary site CI gate, with source footprint coverage in both
profiles; this registration does not claim the protocol driver executes them.
No validator widening or invented wrapper is introduced.

Verification is static YAML and manifest loading, exact preservation comparisons,
closed path existence and changed-pattern coverage. Only test collection is used
to measure declarations. No broad control suite, model, SDK, browser, build,
archive production, permission or signature verification is performed here.
Failure risks include stale receipts after COMMON changes, missing retained
inputs on sparse checkouts, and downstream tests that hard-code old command tails.
Existing image command ordering is preserved; new commands append independently.
A different reviewer checks the frozen patch before normal integration.

Source footprints add only missing exact paths from the reviewed helper/CLI/test/document names and the current fixed web-runtime retained-input manifest: 104 distinct candidate paths before deduplication against existing patterns. Each is tracked at the isolated base. Retained data is fingerprinted as input; its inclusion is not a new grant or compiled-route permission.
