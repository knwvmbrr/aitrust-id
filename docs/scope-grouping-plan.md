# Legacy scope groupings — architecture and acceptance

The preserved master scope defines F-019, F-020, F-021, F-022 and F-029 as legacy
**grouping** jobs. They connect older identifiers to independently tracked signals
or tags. They are not five extra detectors. Deliver the mapping and observable
navigation without pretending their child tags/signals are released. Each child
keeps its ID, completion, owner, failure boundary and independent acceptance.

Implement a bounded versioned mapping and offline resolver. Require exactly the
five preserved parent/member sets, unique existing IDs, matching original titles
and an unchanged 202-record crosswalk. Resolve member progress from the current
ledger; refuse missing/duplicate/unknown/cyclic or changed memberships. Do not
compute parent completion from child accuracy or propagate parent 100% downward.

Build the verified mapping into the existing immutable scope payload. In Scope,
show an explicit “grouping link, not detectors” explanation, child status and
large keyboard/touch buttons to open an exact child record. Unknown scope queries
remain no-match; a missing/invalid mapping fails the build while tag checking
remains independent of scope loading. No new route, capture or storage is added.

Acceptance: positive five mappings, invalid mappings/ledger/source identity
refusals, exact-ID lookup, original 202 IDs retained, child statuses unchanged,
actual browser keyboard/touch navigation and mobile reflow. Close only the five
mapping jobs; real detectors, tag accuracy, human testing and institutions retain
their own open gates. No scopes are removed, renamed or silently retired.
