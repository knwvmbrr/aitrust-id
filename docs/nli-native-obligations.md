# Optional NLI native source and notice evidence

This offline engineering tool supplements the original NLI cohort. It does not
run a model, install packages, approve a distribution or issue any tag. The
original cohort, its unresolved conditions and all earlier observations remain
unchanged. The new author is a former reviewer of that older cohort; this new
implementation requires a different reviewer.

```sh
python3 -I -S -B scripts/verify-nli-native-obligations.py
python3 -I -S -B scripts/verify-nli-native-obligations.py --source-cache /private/source-cache --crate-cache /private/previously-verified-crates
```

The first command re-derives a source-bound graph from the exact reviewed retained
records and notices. It is **not fresh archive replay**. The second additionally
hashes and streams the selected source archives from explicit existing caches,
including registry archives in `source-cache/crates`; nothing is downloaded.
Missing, changed, extra or unsafe evidence fails with a fixed non-content error.
The ordinary NLI checker and other tags do not import this optional tool.

## What is actually bound

Both original22-wheel runtime locks, all16 native wheel occurrences across macOS
arm64/Linux x86_64, exact native member hashes and complete shipped notice texts
remain bound to the earlier observed artifacts. The new graph preserves seven
publisher-checksummed source distributions, the exact LibYAML0.2.5 source release,
540 distinct registry source archives from two selected published Rust lock
unions, and their selected original manifest/license/notice/readme bytes. NumPy's
other retained Rust locks are source test fixtures and are not build-graph input.

The actual ml_dtypes0.6.0 sdist contains589 Eigen header files and an MPL2-only
build declaration. The exact source archive was acquired; it is held privately,
not represented as an already published source offer. LibYAML's original full
notice is added as a **supplement**, with a version-pinned PyYAML source recipe
whose default LibYAML reference is0.2.5. That recipe permits input overrides; it
is not an attestation of either wheel's actual build invocation.

The Linux NumPy notice carries BSD/OpenBLAS/LAPACK terms, GPL3 plus the GCC runtime
exception for libgfortran and LGPL2.1-or-later for libquadmath. Its libquadmath
section points to the LGPL text; this graph additionally retains the complete
original LGPL2.1 text from GNU, alongside the shipped copyright/notice. NumPy
project source does not silently become all corresponding GCC runtime source.
Applicable source/relinking conditions and any exception must be handled in the
actual distribution; a matching filename or hash is not permission.

ONNX's NOTICE declares abseil20250127.0, protobuf25.1 and nanobind2.14.0. Its
protobuf line says Apache2; the separately observed protobufv25.1 upstream grant
is BSD3. Both original records are preserved, rather than silently resolving that
publisher discrepancy. Notice retention and exact applicability remain visible.

ONNX Runtime's complete338,088-byte third-party notice is bound to both wheels.
The70 section byte ranges and source-offer preamble are checked against those
exact bytes. They include MKL/proprietary restrictions and covered-source terms;
notice presence alone does not establish incorporation in a selected binary.
Current official source queries did not recover1.31 source/build identity; even
the repository endpoint was inaccessible. This is a retrieval observation, not
proof the source never existed or that the runtime is proprietary. Historical
`402979a` is an unwitnessed queried identifier, **not an established build commit**.
Only selected native byte prefixes were inspected by the supporting reviewer;
absence of a string in those prefixes is not whole-binary absence proof.

## Remaining distribution actions

The machine graph supplies exact notices, source declarations and explicit
retention/covered-source actions. Actual distribution must carry applicable
copyright/license/NOTICE materials; covered Source Code Form must be supplied or
made available as its specific terms require. Complete source/relinking or an
appropriate offer is not fabricated from a repository URL. The private source
cache is not advertised as that distribution offer.

Published lock unions include optional/dev/target alternatives. They describe
published source dependencies, not an exhaustive incorporated binary graph.
Neither compiler authentication nor reproducible compilation is claimed or used
as a new blanket license gate. Model/card rights and tag accuracy stay under the
unchanged original cohort and their own acceptance. No global F057/X02 closure,
legal clearance, permission promotion or supported-tag extension follows.

Each archive is streamed with128MiB expanded-byte and8MiB retained-text limits;
all retained unique text is capped32MiB before reading/storing. The one exact
NumPy sdist has an explicit21MiB compressed allowance; others are at most16MiB.
Source/spec/content hashes anchor trusted reviewed repository observations;
they are not a publisher signature or protection against an operator changing
the trusted verifier itself. The public evidence contains no private cache path.
