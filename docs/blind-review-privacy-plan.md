# Blind review privacy — architecture before refactor

Protect original examples and independent labels in the existing offline review-packet workflow. Current freeze reads before enforcing its 10 MB bound; compare follows file links and accepts unbounded or duplicate-key input. A directory created private does not make a subsequently imported symlink or malformed form safe. This increment adds functioning safety controls without predictions, model execution, collection, endpoints or a new tag. Human reviewers and accepted sampling remain separate.

Pin an owner-controlled private directory descriptor before reading or creating fixed packet members. Open bounded regular files with no-follow/nonblocking flags; reject publicly readable, wrong-owner, nonregular and multiply linked members. Bound original corpus, manifest, each phone/CSV form and reasons before parsing. Reject duplicate JSON keys, non-finite numbers, invalid Unicode/deep structures, changed original fields, duplicate IDs, wrong CSV headers, incomplete items and invented manifest independence/release flags. Keep v1 file formats, frozen hashes, shuffled order, formula-prefix protection and fixed privacy-safe failures. No original text, reasons or path enters diagnostics; no input is executed.

Validate every corpus row before creating the destination. Use exclusive relative writes in a newly created private owner-held directory. Refuse reused destinations and unsafe parent permissions. If writing fails, remove only the newly created task-owned files and directory after descriptor/identity checks; never modify an existing packet. Comparison preserves disagreement and ambiguous items and never infers reviewer identity or independent validation.

Verify both successful actual CLI preparation/comparison and malformed/path/size/race/failure cases on Mac and isolated Linux, with exact sources and synthetic canaries. Maintain source-bound route/browser receipts, state, changelog, architecture and reproduction instructions; publish through normal protected review. N-015/F-108 remain open for real humans and accepted sampling.

Implementation boundary: reuse the existing CLI with fixed filenames and formats. Separate descriptor-based file safety into tools/blind_review_io.py, parameterized with the checkout root. Final directory symlinks, nonprivate/wrong-owner directories, nonregular/multiply-linked/public members and too-large input are refused before parsing. Pin a private directory FD, open fixed members relative to it with O_NOFOLLOW and O_NONBLOCK, verify descriptor metadata, and read at most limit+1 bytes. Reject input and destination inside this checkout. Parent traversal resolves platform aliases before the final private directory is pinned; this does not claim protection against a malicious same-UID owner moving their private folder afterward.

Prepare all serialized contents and validate all rows before creating the packet. Open a newly exclusive directory relative to the parent FD; verify newly created inode and mode, then create fixed files exclusively relative to that directory FD at 0600. Validate output sizes before creation. On failure unlink only this invocation's own recorded file inodes, and remove its newly created directory only if parent still names its inode and no foreign entry prevents removal. Never remove an existing directory or file. Ensure descriptors close on all paths. Refuse any unsupported platform lacking no-follow and directory-FD support with a fixed privacy-safe error.

The source JSONL is limited to 10 MB; phone JSON forms to 10 MB; frozen items and each CSV to 16 MB; the manifest to 64 KB; and all newly serialized packet members together to 32 MB. Reject excess output before creating a destination. Each packet has 1–1000 unique items, identifiers up to 100 Unicode code points, text up to 200,000, source/category up to 1,000 each and reasons up to 2,000. Spreadsheet-escaped IDs must stay unique. Larger/chunked packets are a separate change.


The phone import also needs strict UTF-8, duplicate-key, scalar-text, node and depth checks. Preserve the public 10 MB phone-file limit; reject larger generated forms before creating any packet. Reuse the existing Review test examples dialog, keep input on device and keep physical/human acceptance separate. No new endpoint or automatic collection.
