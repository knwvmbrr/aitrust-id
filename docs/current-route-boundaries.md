# Personal route boundary review

The current personal preview has no account, payment or receipt requirement. It
checks text on the device, or through an explicitly enabled authenticated local
service. It has no company-hosted content/report upload, promotional publishing,
identity template or automatic research/analytics route. This does not make the
hosting provider, GitHub, or a compromised computer collection-free.

`eval/route-boundaries.json` is the maintainer's reviewed source inventory, not an
independent security certificate. `npm run verify:boundaries` compares the actual
current source and endpoint/access surfaces with it and requires matching executed
extension and website receipts. The site predeploy hook runs it: a changed source,
new route, expanded permission, missing or stale browser check refuses deployment.
Use `AITRUST_VERIFY_PYTHON` to select the Python environment with the locked
gateway and evaluation dependencies. No token or submitted answer is printed.
Build the site first to prepare its checked device assets. The CI definition runs
this browser/deploy test file in the site job after that build, separately from
the network-isolated Python job. No check is dropped. Hosted Actions execution
remains blocked by the previously recorded account restriction; configuration is
not presented as an executed hosted run.

The executable input controls accept ordinary text without an identity or receipt
and reject eleven undeclared fields, including payment, biometric templates,
telemetry, training contribution and report attachments. These are component
controls, not new real HTTP observations. The separately published remote Linux
service evidence covers its current authentication, no-store headers, unsupported
modalities, redaction binding and declared isolation probes. Source-bound browser
receipts cover local custody, pause/reset, no automatic content sharing and actual
current catalogue workflows. Deliberately violating test profiles verify refusals.

Ten records describe the current enforced personal boundaries: X-01, X-03, X-04,
X-06, X-08, X-12, X-14, X-15, N-007 and N-008. Media detection remains deferred; reserved
hash formats do not become detectors. Public synthetic bug discussion on GitHub
is a third-party community workflow, not child-safety evidence hosting. Never post
private, exploitative or unlawful material there. The company has no such intake.

X-03 follows its revised scope: no unapproved automatic central collection;
research collection remains unconnected. X-14 now enforces registry deferral in
the 0.1 runtime; its refusal launcher cannot start a listener or storage. D11 and
the future registry proposal remain unaccepted. The proposal stays in scope.
X-02 needs an actual license audit; artifact pinning alone cannot close it. Future
consented research, organization services and media methods require their own
accepted boundaries and source review before connection. Editing a manifest can
still be a bad human review: hashes detect change, not semantic safety.
