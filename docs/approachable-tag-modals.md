# Approachable tag modals

Architecture plan · 2026-10-09 · Codex

Keep each tag’s claim, scope, method and release gate independent. Add a separate presentation layer with a plain-language introduction and an everyday example for all 20 entries. Put the working action before the technical evidence. Keep implementation instructions and complete technical fields in accessible disclosures. Use the same presentation contract in the modal, static reference and no-script catalogue.

Enterprise descriptions remain proposals. Correct the catalogue-description export versus evaluated-result distinction, disclose ChatGPT content-script access, keep security reports private, and remove the unrelated missing host-operations reference. Separate a reviewable design from an enforced permission or active service.

Risks: warmer wording must not promise accuracy or availability; examples must not invent results; catalog downloads must not be mistaken for evaluated records; moving controls must preserve focus, keyboard access and static parity. No detector, threshold, taxonomy, collection or pricing change.

Acceptance: all 20 introductions and examples visible; working PS action easy to find; complete specifications and exports retained; enterprise factual checks against the manifest and real export implementation; built site passes light/dark, 320px, 200% text, keyboard, axe and static-page checks. Verify production after publishing. Human usability and screen-reader acceptance remain pending.
