# Per-route dependency conflict controls

Implementation plan recorded before feature code. Base source: 4421ab58b625c8a93203f378de45ac591465b276.

The current inventories prove selected bytes and preserve notices. Their deliberately false coverage and clearance flags stay unchanged. Add a separate, versioned technical policy for actual distribution routes. It must refuse an unknown route, changed input, missing notice, required proprietary processor or required processing payment. An optional route becomes required only when selected and cannot disable unrelated runtime tags. No assertion of legal clearance or independent detector accuracy is produced.

## First complete artifact

A PS-only source ZIP contains exactly the six reviewed processing inputs, the project Apache license, the retained Unicode notice and a short operating guide. It contains no Python interpreter, OS, npm binary, model, personal input or service token. Existing CPython 3.12+ on macOS/Linux is an explicit prerequisite; the evaluator source is parsed into the existing stdlib projection, never imported as a FastAPI service. The entire-repository snapshot is a different, uncleared scope.

## Architecture

- `eval/dependency-policy.json`: closed route map, exact source and notice identities, required processors, platform prerequisites, technical review evidence and per-distribution obligations. Unknown scopes remain registered and refused; none is removed to improve the completion count.
- `tools/dependency_policy.py`: bounded standard-library verification with allowed, blocked_unknown, prohibited and paid outcomes; no network, package execution, credential, automatic exception or self-declared legal permission. `require_route` admits only an actually reviewed source profile.
- `scripts/check-dependency-policy.py`: fixed, safe per-route diagnostics and machine output. Unrecognized or incomplete selection refuses.
- `tools/ps_source_distribution.py` and CLI: invoke the actual policy, read exact regular source members without links, verify source stability, create a deterministic bounded ZIP, inspect every output member and publish atomically without overwrite. Verification compares to the independently selected current source policy; a carried manifest is not an authenticity credential.
- Existing full-source, website, native and container release profiles stay separately identified. Reviewed release consumers must refuse blocked included scopes; preview/source-observation workflows must not claim that observation is release approval. Integration is explicit and does not silently disable existing runtime checking.

## Risks and proof

Input drift, forged allowed flags, substituted notices, missing/extra ZIP members, links, duplicate JSON/ZIP fields, unsafe paths, resource exhaustion and output replacement must refuse before publishing an artifact. Policy and code are trusted reviewed repository inputs, not a tamper-proof authority or a legal opinion. Source-only licensing does not approve unbundled interpreter/OS distributions or other native artifacts.

Execute an actual nonempty source export, isolated extracted finding/no-finding operation, offline Linux operation and absence of third-party package requirements. Exercise real refused exports for changed/unknown/paid/proprietary or missing-notice dependencies; no partial output may survive refusal. Preserve historical evidence. Run only affected integration/required checks after focused controls pass.
