# Q4 2026 brand and parallel delivery plan

Owner direction: 2026-11-16. Implementation and integration lead: Codex.
This is an enhancement to the existing 202-record scope, not a replacement.

## Architecture before changes

Use one woodland camouflage visual language on the website, native checker and
Share extension. Preserve the tag logo, tag codes, rounded typography, semantic
result wording and disclosure boundaries. Keep camouflage on decorative margins
and background surfaces; text, input, evidence and modal panels use opaque solid
surfaces. Light and dark appearances use the same semantic palette in web CSS
and native dynamic colors. Pattern patches use 30% opacity: subtle, original rounded woodland forms,
inspired by streetwear camouflage without copying another brand's marks or art.
Pattern is static, decorative and absent from the
accessibility tree. Forced colors, increased contrast and reduced transparency
retain readable solid surfaces. This Q4 theme remains explicit until the next
review; do not silently change the product by local clock or download remote art.

Web and native renderers share palette and organic silhouette geometry, without
introducing a rendering dependency between platforms. Native packaging must
include its theme source in both app and extension, and source-bound build
verification must hash it. Theme changes cannot imply detector improvements or
transfer an earlier Apple validation to new bytes.

| PM and integration | root | Scope, state, change events, evidence, branch integration | No unrelated files, preserved acceptance, protected CI |

Agents own disjoint files. They report changed files, executable checks, observed
failures and remaining acceptance to the PM. No agent independently changes tag
status, scope completion, legal promises, telemetry, paid services or deployment
permissions. Parallelize independent investigations and implementations; serialize
shared builds, integration and final publication. Current concurrency is three
specialists plus the PM, so a lane is reused when its accepted increment finishes.

## Independent tag lanes

Each of T-PS, T-PII, T-MT, T-NF, T-FI, T-HP, T-IV, T-FA, T-PA, T-UNK,
T-OUT, T-UC, T-SC and T-BT retains a separate contract and acceptance record.
A tag agent owns that tag's input boundary, evidence method, version, regression
corpus, misuse cases, performance budget, failure behavior and concise result.
No tag verdict is a prerequisite for another tag. Shared transport and security
controls must not convert an unavailable sibling into a clean result. A bounded
software observation is not a released semantic tag.

Prioritize existing PS/PII reliability and the native app, then choose the next
bounded tag-method increment from the preserved scope. UC/SC/BT proposal adoption,
independent accuracy, human acceptance and other owner-only gates stay open.
The PM must not allocate fabricated independent reviewers or close requirements
merely because an agent wrote tests. Planning all lanes does not mean all are
currently staffed or running. Scope progress remains evidence-driven.

## Proprietary AI track

A project-specific assistant is a possible separate enhancement under N-010,
not an adopted production model or a new gate on personal checks. Its first
bounded job would explain existing evidence and suggest review tasks with source
citations. It must abstain when the evidence does not support an answer; it must
not issue or independently validate its own tag claims. Before training, define
an evaluation set, allowed inputs, license/permission lineage, deletion policy,
security boundary, compute budget and release/rollback gates. No user text,
public issue or optional research feedback becomes training permission by use.

Start by measuring an inspectable open-weight baseline with retrieval over public
project documents. A private fine-tune or closed weight component is a separate
choice requiring a clear advantage, legitimate data rights and transparent
component labeling. It must not contradict the free, inspectable personal tag
contract or silently turn an open-source product into a closed service. No
training, model purchase, telemetry or data collection is activated by this plan.

## Risks and release evidence

Camouflage can obscure meaning: measure text/control contrast and keep solid
reading surfaces. Native source changes invalidate old build proofs: regenerate
current source/package evidence. Search snippets can imply unavailable features:
derive status from the same catalogue presentation contract. Google ranking and
indexing need separate measured evidence; a sitemap alone proves neither.
Neither agent count nor passing development examples is independent accuracy.
Keep actual run outcomes and remaining owner gates visible in the scope and
changelog. No new API or paid resource is introduced.
