# A complete private citation practice packet

## Job and outcome before implementation

Make the existing FI resolution-evidence CLI approachable from a clean clone.
One preparation command creates a fixed invented subject, corpus-v1 and declared
number-to-document sidecar; the second existing canonical checker reports one
resolved occurrence, one unmapped occurrence and one unsupported bracket form.
No manual hashes, context JSON, model, package, account or network is needed.
This is a local computer command workflow, not a phone/browser implementation.
Full T-FI contextual, independent-error, mapping and human acceptance stays open.

## Architecture

Only a new scripts/prepare-citation-demo.py, practice guide/plan, focused tests and
attributed evidence/changelog. Leave canonical citation_resolution.py and its CLI,
corpus format, normalizer, all other methods and shared integration unchanged.
The new script calls the current canonical _prepare and _check with descriptor-
captured source identities. It validates the fixed example before saving any file.

Create only a new named 0700 directory in an existing owner-private 0700 parent
outside the checkout. Traverse ancestors through the canonical Capture helper's
no-follow descriptors; never follow links or replace existing names. Create the
three fixed files subject.txt, corpus.json and citations.json exclusively at0600.
Own raw descriptors immediately, use fdopen(closefd=False), and attempt every
owned close exactly once. Recheck source and directory/file identities before
success. Default console JSON contains no subject, IDs, paths, spans or hashes.
Source/corpus/subject identities are confined to the deliberately created JSON.

## Failure and privacy risks

The packet is owner-private but contains invented source/subject text because
preparing it is an explicit save. It never reads a real example. An unresolved
mapping does not mean a source is absent elsewhere; unsupported is not false.
Resolution proves only the caller's declaration against attached bytes, not
source truth/authenticity, claim support, correctness or an FI verdict.

Existing destinations are untouched. A pre-success failure attempts removal of
only this invocation's verified files/directory and closes all handles. If cleanup,
publication outcome or a post-success close cannot be confirmed, report fixed
UNAVAILABLE with output_may_exist:true; keep the private evidence and inspect the
selected directory before retrying. Never silently claim rollback when the
filesystem refuses it, remove an unrelated entry, or retry a possibly reused fd.
The OS owner, checkout/source and filesystem remain trusted; no forensic erasure
or hostile same-account defence is claimed.

## Focused verification after implementation

Run actual two-command practice, exact canonical source/sidecar/count parity,
private modes, no default text/path/hash output, no overwrite, invalid arguments,
unsafe parent/link/FIFO/destination cases, source drift and injected write/close/
cleanup failure. Confirm another independent checker remains usable when this
optional preparer fails. Use fixed synthetic fixtures only. Preserve any failed
candidate separately; no broad suite, Docker, browser, deployment, current Linux,
independent accuracy, human operation or original requirement closure claim.
