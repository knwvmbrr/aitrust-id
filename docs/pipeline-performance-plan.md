# Staging pipeline performance — architecture before implementation

Measure the existing /healthz and /v1/evaluate loopback endpoints on an already-running, explicitly selected staging system. Do not create an endpoint, start local Docker, modify production services, capture real text, or introduce accepted latency budgets. The authentication token comes from one owner-private non-symlink file and is never printed, embedded in reports or passed as a process argument. No proxy, redirects or arbitrary hosts are allowed.

Generate fixed synthetic no-finding, command-pattern and redaction-plus-command inputs at declared 256, 2,000, 8,000 and 20,000 normalized codepoints. Send sequential, bounded requests with a hard timeout and validate response identity and assertion schema before accepting timing. Separate the first observed request (not a claim of service cold start) from repeated warm requests. Record exact character/UTF-8 counts, client round-trip durations, returned gateway pipeline durations (wire field evaluator.latency_ms), sample count, nearest-rank median/p95/max and selected component source hashes. Reject nonfinite timings, unsupported responses, missing privacy headers and changed model identity.

Default report includes hardware/OS/runtime conditions and summary timing only, without response text, IDs, hashes of synthetic subjects, tokens, endpoints or private file paths. Failure retains bounded stage/profile/completed summaries without raw upstream errors. Full-chain measurements include HTTP loopback, redaction and evaluator processing; they exclude phone/network startup and do not establish recognizer accuracy. A changed source invalidates comparisons. Existing 100 ms remains an unaccepted candidate target.

Test malformed tokens/file permissions/symlinks, redirection refusal, source identity, assertion errors, synthetic forms/lengths, repeat counts and quantile calculation, bounded timeout/failure reports and credential/canary non-reflection. Run actual requests on isolated staging only; no participant collection. F-113 stays open pending physical phones, declared budgets and final acceptance.

## Published timing detail

Use build-time, source-bound measured data; no runtime request or collection is added. The PS and PII_REDACTED evidence sections may show a compact four-row service timing chart, explicitly naming the full redaction-plus-tagging route. Keep phone/browser emulation timing separate. The four displayed points are the maximum warm p95 across three synthetic profiles per input size, not accuracy, latency confidence intervals or an accepted speed budget. Other tags receive no borrowed results.

Validate the exact source inventory, finite sample values, 20 samples per profile, exact nearest-rank summaries, all 12 unique profile/length combinations, declared hardware and synthetic-only classification before building. Publish a canonical JSON artifact without input text, identities or credentials. A stale source or fabricated summary fails the build. Use an ordinary details control, labeled values and decorative bars; support keyboard use, light/dark, 320px layout, zoom and static HTML. A plain download exposes all measured data and conditions. No tags, protocol fields or production methods change.

## Review correction: every timed service identity

The initial benchmark matched only the evaluator source. Local gateway/redactor hashes and a separately recorded container witness did not make those checks intrinsic to each timed response or the build. Require the existing preprocessing identity on every assertion, validate both identity digests, match gateway/normalization and all five redactor source identities to the selected checkout, and require model entries to match their preprocessing digests. Keep one identical full runtime identity across the run. Publish that non-content configuration and check its shape/digests/source bindings before admitting the timing display. Re-run actual staging requests and stale-gateway/redactor/digest/model/drift refusal controls. A service’s self-reported identity is not cryptographic remote attestation and a compromised service can lie; keep that limitation explicit. The earlier measurement is historical and must not pass the corrected build.
