# Selected asset notices: architecture and acceptance

Codex · 2026-10-12 · F-057 / X-02. This increment protects recipients by keeping third-party notices with the resources they receive. It does not change a tag, introduce an endpoint, collect user data or grant legal permission.

Before implementation, the design is an offline, bounded consistency check for the five self-hosted font files and their OFL notice, CSS, frozen Unicode data and consumers, retained runtime notices, and the pinned optional model card. An observed upstream runtime archive can be reprocessed without extraction or execution; prepared runtime bytes are checked separately against those retained upstream member identities. Checking declarations is distinct from reading model weights or reviewing every transitive dependency.

The verifier binds exact metadata and verifier source hashes, sizes, digest identities and notice associations. It rejects missing, changed, linked, malformed or extra entries, false clearance flags, and altered prepared runtime bytes. The native package must carry the exact frozen Unicode notice as well as the existing runtime notices. Reports remain engineering evidence; requiring legal clearance must still fail.

Risks retained: native and compiled transitive libraries, additional platforms, source-offer obligations, model permissions and qualified legal review. F-057 and X-02 remain open until their full acceptance criteria are met. The observed metadata cannot authorize redistribution by itself. No automatic refresh silently accepts changed upstream assets.

Acceptance for this component: source-only verification in a clean checkout; corruption and false-clearance refusals; actual pinned runtime archive comparison; exact notice inclusion in website and native resource packages; compatible CI; attributed change record and immutable run evidence. Physical-phone testing and independent tag accuracy remain separate.

Documentation repair before changing the renderer: preserve dated executed-component notes after the generated master table. Re-rendering must retain those notes exactly and avoid duplicating them; it must not modify any scope IDs or acceptance criteria.
