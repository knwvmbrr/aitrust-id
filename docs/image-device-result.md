# Standalone private image preview: executed handoff

The isolated component now runs the exact reviewed PNG/JPEG metadata algorithms
in a fresh browser worker. A user chooses a local file, explicitly inspects it,
and sees bounded header facts and fixed metadata-category counts. No image,
filename, embedded value or result is uploaded or stored. Default summaries hide
the encoded-file hash; exact JSON is an explicit private detail with a linkability
warning. The original file remains unchanged and may still contain private data.

This is useful image-evidence software, not an image-origin detector, C2PA
validator, pixel decoder, authenticity/truth check or FA/PA verdict. No original
requirement closes. The text-only gateway and adopted tag codes are unchanged.

The builder pins the whole two files and projection inventory, then checks every
top-level AST node's kind/name/source-segment digest. Only the explicit pure

source, OS/file/process supervisor, image-selected executable or dynamic source
acceptance is used. The browser verifies the exact projections and all five
existing Pyodide314.0.7 runtime files. No package or model is installed.

PNG retains its selected noninterlaced8-bit profile, CRC/order/zlib/scanline
checks,4-million-header-pixel and32-MiB expansion limits. JPEG retains its
selected8-bit baseline single-scan framing profile and does not validate entropy
codes or pixels. Unsupported valid variants are not called corrupt or AI-made.
Metadata-section labels are untrusted; APP11 and C2PA-shaped sections are opaque.

A real Blob's intrinsic size is checked before an abortable FileReader is
created:10MiB maximum. Startup/capture has a45-second bound; evaluation6 seconds.
Cancel, file change, Clear and unmount stop owned work and invalidate late replies.
Closed response schemas bind the exact encoded bytes, size, parser/projection
identity and header facts before anything can render. These checks trust the
hash-verified canonical worker; they are not independent semantic validation.

This branch edits no shared main/catalogue/prepare/package/eval/state/scope/CI
files. The runnable standalone fixture uses the unchanged real HandheldDialogs
PS checker and existing MTExplorer as independent failure controls. Its build is
not the normal public website distribution or protected-publication proof.

Root owns a future closed optional FA helper mount, guide copy and normal build
registration, privacy/presentation review, current-source integrated controls and
publication. PA stays unchanged; FA stays Planned and unissued. The existing
normal public-runtime source/notice postbuild gates must remain in place when
integrated. No whole-dependency license or redistribution clearance is claimed.

The selected component paths are `/device/image-metadata/manifest.json`, its
content-addressed `method-*.json`, `image-metadata-worker.mjs` and
`project-notices.txt`; runtime files remain `/device/runtime-314.0.7/`.

be mounted only after an explicit disclosure open and unmounted/epoch-reset on
close, including coalesced close/reopen. The fixture demonstrates that lifecycle.

The shared on-device runtime can be cached by other supported app workflows, but
this component has no independently established offline installation/use claim.
On-device computation does not guarantee offline availability. No new service
worker or storage permission is introduced here.
