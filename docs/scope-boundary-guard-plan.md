# Executable scope boundaries

Keep all excluded ideas in the scope; implement a release guard for the current
0.1 routes rather than silently deleting their rows. Each rule names its observed
surface, negative control and limits. The guard checks protocol output policy,
shipped extension permissions, site export and privacy choices, active compose
services and current advertised capabilities. It cannot prove every future change
safe or replace independent release review.

Do not count a rule as complete from this document. Positive and deliberately
violating fixture cases must run, and the actual current surface must pass its
rule. A future feature may reopen a boundary or require an explicit owner decision;
this guard must never promote a planned detector, form an institution, or grant
training permission from public discussion.

Risks: static source scans can miss semantic changes and third-party behaviors;
network probes cover only their declared channels; host compromise lies outside
the extension's closed shadow root. Version the guard and test its inputs rather
than claiming an all-purpose security proof. Paid infrastructure does not make
the open-source personal processing pipeline a paid inference API. Owner-held
research PostgreSQL is distinct from a central store of assertion history.

research interpretation against missing/context-only evidence, eight adopted
but disabled codes, six unknown accusation/proposal codes, missing/incomplete
credentials and a human-origin claim. No context or absence can create FA/PA/IV;

This verifies F-083, X-05, X-11, X-16 and N-009's current enforced refusal jobs.

open. The production HTTP contract was separately exercised on the current
Linux image; component tests are not presented as new live credential parsing.
