# Independent footer workflows

The tag grid and theme remain the main product surface. Footer entries get unique
addresses, descriptions, content components, action contracts and exported records.
Sharing accessible dialogs, buttons and theme tokens does not merge their jobs.

| Entry | Job and result | Primary path |
| --- | --- | --- |
| Report | Describe observed and expected tag behavior; export a reproducible issue | Public issue template; vulnerabilities go to the private channel |
| Assist | Select a contribution and its deliverable; export a volunteer proposal | Review instructions, contribution guide or pull requests |
| Townhall | Find public questions, proposals and announcements | Verified GitHub discussion categories; no fake in-site posting |
| Teamwork | See accountable owners, open needs and acceptance evidence | Pick a specific contribution; no unconfirmed assignment |
| How tags work | Walk through input, observation, limits and challenge | Real PS checker or complete tag reference |
| Scope | Search and filter every preserved record; inspect jobs and outcomes | Download the scope; no planned feature presented as shipping |
| About | Understand mission, principles and current product maturity | Source, working checker and roadmap |
| Legal | Inspect licenses, data handling and unresolved organization/mark status | Actual license texts and private vulnerability reporting |

Risks: forms must not put draft text in outbound URLs, confuse download with
submission, expose vulnerabilities publicly, or make one workflow depend on another
being completed. Public discussions require GitHub accounts; the site has no
posting service. The discussion snapshot is explicitly dated, with a live external
reader link. Empty states give one clear next action. Search and forms must work
on phones, keyboards, enlarged text and both themes. Each address must reopen its
own panel without changing the tag audience. Clearing or closing one workflow
must not leak its values into another.

Verify every workflow's actions, destination, export shape, failure behavior,
focus and responsive layout. Preserve the working device checker and all tag
modals. Deploy only after those checks pass; retain the prior Pages deployment
for reversal. First-use/name evidence is a separate dated record, not a site
marketing claim or legal clearance determination.
