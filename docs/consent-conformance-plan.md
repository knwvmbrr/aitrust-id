# Consent and claim controls — execution plan

Preserve all 202 requirements and every planned tag. This increment addresses
F-128 (optional receipts), F-144 (mark guidance and a usable self-declaration),
and X-07 (the image-provenance boundary). It creates no endpoint, accounts,
training intake, certification programme, legal entity or new tag release.

## Architecture

A dependency-free shared consent policy validates the reference editor's policy
before observation or export. Writing/observation never requires a receipt;
issuance remains an explicit author action. The same validator is callable by
future organization integrations and refuses mandatory attestation, collection
or denial of ordinary use without a receipt. Unknown policy fields fail closed.
Actual browser tests exercise writing, declining exports and reset without keys,
receipts, network or storage. Policy fault tests include organization overrides.
This controls our implementation; it cannot stop an employer demanding a file.

A local conformance statement command produces a versioned, inspectable
self-declaration from actual local evidence files. It binds their bytes and
reports declared check results, source revision, limits and issuer. No checkbox
or passing engineering test grants a certification mark, proves accuracy, or
establishes trademark clearance. Separate usage guidance covers attribution,
modified implementations and permissible descriptive reference. The authority
and certifier programme requirements remain separate.

An executable release boundary checks the current producer, consumer catalogue
and explicit future release policy. It rejects image-provenance issuance and
self-issued C2PA replacements while permitting inspection of C2PA evidence and
other preserved research. Tests mutate future configurations and execute the
current gateway's unsupported-modality behavior. Adjudication is not a claim
that this project issues image-origin credentials.

## Risks and verification

A policy parser alone is insufficient: integrate its decision in the actual
editor and test both browser engines. A declaration may contain false inputs:
label every result self-declared and never grant certification. Never publish
private evidence or keys automatically. Outputs are local, bounded, reject
symlinks/overwrites, and use the existing atomic publisher. No claim of legal
clearance, protection from institutional coercion, independent validation or
physical-phone acceptance follows from this engineering increment.

Before completion: positive, malformed, mandatory-policy, cancelled-export,
missing/tampered-evidence and prohibited future-release controls; full regressions;
source-bound revalidation; updated scope, changelog, state and execution evidence;
normal protected PR and publication checks. Counts change only after full named
acceptance is functioning. Other incomplete records stay open.

## Additional executable job: F-020a local corpus support

Reuse the existing private, integrity-checked corpus; do not change its format,
start a service or send source text anywhere. Add a separate local retrieval
command, with nonempty input lines as declared claim units and nonempty corpus
lines as reference passages. Bound counts, tokens and results. Compare ASCII
word-frequency cosine similarity; report exact NFC scalar spans, source/corpus
identity, method parameters and unestablished reference freshness. Other languages
are unsupported by this first method rather than silently treated as negative.

This implements the existing retrieval-similarity signal, not factual checking.
Negated, dated, quoted and fabricated-but-similar statements can match; tests must
show this limitation with no NF/FI or truth conclusion. No threshold is a
probability or adopted tag confidence floor. Mathematical, span, tampering,
missing-corpus, non-ASCII and CLI controls establish the component's acceptance;
NF and FI accuracy, NLI contradiction and independent review remain open.
