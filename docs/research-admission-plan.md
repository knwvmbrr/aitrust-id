# Synthetic research request boundary

Architecture before implementation; Codex. N-011/F-141 component only.

The existing SQL profile accepts digests from a trusted caller. Add an independently
runnable development admission CLI and strict Python request translator to exercise
that boundary with invented records. Reuse the existing metadata field/value
allowlist and SQL invitation/withdrawal functions. No public endpoint, daemon,
production login, real invitation issuance or automatic browser upload is added.

A private 0600 request in an owner-held 0700 directory outside the checkout has a
closed synthetic-only versioned envelope. Submission requires canonical 32-byte
base64url invitation and withdrawal bearer values plus the existing PS local-export
metadata. Withdrawal requires only its bearer value. Reject duplicate/unknown
fields, text, identity, timestamps, hashes, nonfinite values and oversized input.
A translator emits fixed SQL with hexadecimal encoded canonical metadata and
SHA-256 token digests; plaintext tokens never enter SQL, command arguments,
diagnostic output, database rows or public receipts. No tokens are generated by
this CLI. Verification uses publicly declared invented fixture values only.

The executable may connect only to a freshly owned private socket-only PostgreSQL
18 sandbox using the existing strict directory guard. Verify actual data/socket
paths, no TCP listener, dedicated synthetic cluster name, database and version
before any insertion/withdrawal. Environment is allowlisted; trusted bootstrap
peer connection sets the existing NOLOGIN intake role inside a bounded transaction.
This tests capability admission and selected role behavior, not production login
authentication or isolation from a compromised administrator. Refuse production
paths before invoking psql. Bound SQL/process time and output, return fixed errors,
and print only bounded result IDs/withdrawal outcomes after successful parsing.

An independent admission sandbox profile applies the existing two SQL profiles,
then invokes the real CLI for valid/duplicate/conflicting requests, malformed and
private fields, wrong/expired/revoked invitations, quota rollback/oversubscription,
withdrawal/replay, hostile file/sandbox paths and diagnostic/token privacy. Ensure
actual database shutdown/cleanup; retain bounded failures. Preserve independent
base/invitation profiles and source-bound CI. Tests must cover parser parity with
the website's fixed choices and actual PostgreSQL round trips, never count invented
ratings as accuracy evidence. No detector, tag allowlist or personal workflow changes.

Risks: tokens grant bearer capabilities and must stay private; their digests can
link records. Exporting metadata is not consent to upload. Trusted database admins
and local host compromise remain outside this development assurance. The existing
30-day/7-day intervals are development behavior, not an adopted participant policy.
A real pilot still needs approved endpoint/purpose/roles/retention/withdrawal rules,
reviewed proxy/provider handling, genuine authentication, encrypted backup expiry,
replacement-host recovery and a consenting participant. N-011/F-141 stay open.
