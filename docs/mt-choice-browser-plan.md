# Optional browser practice for selected choice wording

## Architecture and outcome before implementation

Build a complete standalone, unpublished practice page around the reviewed
choice-framing 1.3 method. Keep the current MT preview, catalogue, canonical
method, CLI and other tag workers unchanged. This is literal wording evidence,
not an MT tag, a false-dilemma accusation or a new detector accuracy claim.

The person explicitly chooses the whole pasted passage as the frame (at most
2,000 original/NFC code points and 8,000 UTF-8 bytes), two exact item strings
(at most 256 code points each) and an additional nominated passage (2,000 code
points/8,000 bytes). Each item must occur exactly once in the normalized passage,
in the supplied order. This is a deterministic caller declaration, not automatic
clause selection. Ambiguous, missing, overlapping or stale selections refuse.
The additional passage is not verified as relevant, feasible, authentic or fresh.

A new Python wrapper makes the canonical corpus-v1/context-v1 values and invokes
unchanged choice_framing.observe. A separate fresh browser worker loads the
hash-checked Python source bundle in the existing pinned Pyodide runtime. Input
is a bounded JSON function argument, never executable Python or interpolation.
Return the complete canonical observation plus exact raw-request, raw/NFC
subject/reference, selected-item and source identities. Bind before display with
closed result records, exact hashes, counts, spans and literal marker checks.
Private details are not mounted until requested. No input is uploaded, logged,
automatically stored, exported or used for research/training.

A standalone builder captures no-follow regular source files, rechecks identity,
checks all five cached runtime assets against the tracked release manifest, and
copies notices plus the existing selected JavaScript/zlib source exports. It does
not install dependencies, fetch packages, execute captured source or alter a
shared public route. Build only a new destination; report uncertainty if output
cleanup/publication cannot be confirmed. Existing output is never overwritten.
Runtime/source downloads are public static files. Their hashes identify bytes,
not global legal clearance or complete WASM corresponding source.

## Interface, lifecycle and failure

Use compact left-aligned rounded system typography and opaque reading/input/
result panels with the shared woodland palette, static low-presence background,
light/dark adaptation, keyboard labels and at least 44-pixel controls. Fixed
examples cover additive and the four earlier constructions. Default page mount,
example load and editing start no worker or analysis. Check is explicit and
requires the whole-frame declaration. Preserve whole oversized pasted input and
show Unavailable; never clip it into an accepted example.

Every Check owns a fresh worker, with 45 seconds for startup and 6 seconds for
execution/validation. Clear, editing, another Check, Cancel and page disposal
terminate ownership and invalidate late replies/results. Busy/invalid/integrity/
worker/timeout failures are Unavailable, never zero observations or safe. Other
page controls and existing tag routes remain independent.

## Risks and acceptance limits

Additive wording must not become a binary-choice warning. Keep additive markers
separate and the canonical null proposal. Ordinary choices, ranges, quotations
and legitimate safety advice remain literal observations with unresolved intent,
negation scope, exhaustiveness and additional-option feasibility. The UI displays
no production signal/tag or probability. The trust boundary is the verified local
source/worker; hashes and schema validation are not cryptographic verdict proof
against an already compromised page or OS.

Implement first, then focused wrapper/builder/client controls and actual complete
Python/browser record comparisons. Browser work waits for the PM's heavy-test
slot. Capture actual mobile-sized Chromium/WebKit use, no default analysis,
private details, edit/clear/cancel/stale behavior, oversized input, corrupt sources/
results and failure recovery. Keep earlier failed candidates. No production
deployment, physical-phone, human accessibility, independent accuracy or full
F-019b/T-MT acceptance follows from this experimental workflow.
