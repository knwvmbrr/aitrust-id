# Next mobile build candidate — N-013 native iPhone sharing

Architecture before code, 2026-10-11: isolated optional native containing app and Share extension. Accept selected plain text only after an explicit Share action; preview, edit, confirm check, clear and cancel must work with accessible system controls. Input is bounded, kept in ephemeral memory and never placed in URLs, app-group storage, analytics or notification logs. No account, custom endpoint, collection consent or production change is introduced.

The existing exact-source PS method must remain the checker; a Swift approximation of its regex rules cannot claim parity. Investigate a bundled offline WebKit route or a strictly bounded bridge into the already tested checker before selecting an implementation. App signing, real iPhone share lifecycle and VoiceOver remain owner/device acceptance; a simulator result is separate. Do not write a nonfunctional Share extension merely to advance a count. If the SDK/runtime is unavailable, retain the diagnosed block and move to the next buildable requirement without an owner question.

Security risks to resolve before implementation: remote content must never receive raw input without explicit same-checker purpose, redirects/query/body leakage, untrusted JavaScript bridge injection, file/link handling, overlong share payloads, extension deadlines, memory lifecycle and unintended auto-check. Check bundled method hashes and exact fixture parity. Native and browser routes must not become mutual prerequisites.

Observed file-route refusal: the iPhone simulator denies bundled module loads under file-origin CORS. Do not enable private WebKit file-access preferences, loosen HTTPS policy or introduce a local HTTP server. Before another experiment, test a bundle-only WKURLSchemeHandler resource loader: an explicit immutable public-asset URL-to-byte/hash allowlist, no user data in URLs, no external navigation, and all query/fragment/traversal or unknown asset requests refused. This is an app-internal resource scheme, not a new network service or collection endpoint. Validate every resource against its build fingerprint and retain the failing file-origin receipt. Production/native share work remains unimplemented until the existing exact checker runs and memory/lifecycle/interaction bounds are exercised.

Bounded implementation selected after actual compatibility: a containing UIKit app plus a Share extension, each bundling the exact prepared PS Python/WASM method and public runtime assets. Keep the native wrapper open source, with Apple's SDK/OS identified as the host platform rather than an open-source runtime claim. A generated Xcode project copies only listed public sources/assets/notices into a new owner-private output directory; no credentials or signed phone profile are generated. Simulator build/signing uses ad-hoc development identity only.

The Share controller accepts exactly one supported text item, previews it and waits for Check with PS. It cannot load file URLs, concatenate multiple selected items, read the clipboard automatically or start a network service. The containing app supports explicit pasted/typed text and an invented practice-share action. Editable input, short result, optional matched excerpts and clear/cancel controls use Dynamic Type, system contrast/rounded body fonts, left alignment and 44-point minimum controls. Input changes invalidate the previous result.

Native-only bundle resource loader admits exact scheme/host/path/method names from a fingerprint map, refuses query/fragment/traversal/unknown routes, verifies asset hashes and supplies a restrictive CSP. The JavaScript bridge accepts text as an argument, never source code or URL data; reuses the same frozen Unicode normalization and method; validates current PS result identifiers before explaining excerpts. All data stays in ephemeral native/WebKit memory, with no app-group store, account, background telemetry or upload. Native host deadlines and generation identities discard canceled or stale outcomes. Do not claim process termination or physical extension memory safety from an app-level simulator result.

Tests must execute actual generated builds and the simulator's host/Share extension interaction, compare the complete existing synthetic development corpus and Unicode witnesses to the original method, exercise malformed input/bounds, editing/cancel/recheck, asset tampering/network refusal, and inspect light/dark/large-text UI. Record SDK, simulator OS, source/asset hashes and timings. A simulator cannot establish physical iPhone memory/lifecycle, device signing/install, real VoiceOver or independent accuracy; those remain separate final acceptance. If extension startup exceeds its memory/time constraints, keep it unavailable and retain the failure rather than substitute approximate rules or route text through a URL/server.

Before adding the UI automation target: use XCTest against only the dedicated clean simulator and this app/Share extension, with invented text and the practice-share action. No personal clipboard, browser, credentials or real participant examples are read. Simulator ad-hoc signing creates no new authentication credential. Keep build and UI failures as receipts, and keep the native route unavailable publicly until the selected actual path has passed.

Use the declared plain-text item request and accept only its returned String, rejecting Data, URLs and other objects. This API has no cancellable Progress: cancel/clear/deadline invalidate and discard later callbacks, without claiming that the provider's work was terminated. Keep the 10-second delivery and 20,000-codepoint bounds; real provider memory limits remain unproved. This change must pass the actual Share test rather than being inferred from the API's presence.

The declared plain-text item request returned successfully with no error but was not a String. Permit only String or a strict UTF-8 Data representation bounded to 80,000 bytes before decoding, then enforce the same 20,000-codepoint check. URL/file/attributed/unknown objects remain refused; no automatic file loader or encoding guessing is added. This is a transport representation change, not a broader content capture capability.
Before implementation: investigate the system-provided temporary-file representation of the single declared plain-text share provider. Do not read a URL returned as an arbitrary item or fetch any URL. Use only the copy returned by loadFileRepresentation for public.plain-text.
