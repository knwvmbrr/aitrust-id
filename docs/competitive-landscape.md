# AI Trust ID competitive landscape and delivery priorities

As of October 8, 2026, 86 products, projects, programs and standards overlap with some part of AI Trust ID’s scope, plus 8 candidates requiring confirmation. This is a comprehensive working inventory, not a claim that every competitor worldwide has been found. Products with the same parent can appear separately; standards and dependencies are distinguished from sellers. Official pages establish published capabilities, not independently proven accuracy.

AI Trust ID’s opportunity is a small, understandable tag with a specific job, inspectable evidence and a reproducible method. These qualities must be demonstrated. Our current PS and redaction workflow is a development preview; neither has passed independent accuracy release gates. A cleaner website does not change that status.

## What the inventory does and does not establish

The inventory is not 86 copies of AI Trust ID. It includes partial substitutes, enterprise products, implementation frameworks, standards and similar names. No reviewed product has been verified here to implement the complete proposed workflow: multiple compact code tags beside an AI response, each bound to specific evidence and a versioned method, with independent per-tag acceptance gates and personal versus enterprise use. That is an unverified equivalence question, not proof that no equivalent exists.

There are closer overlaps than authorship detectors. [TrustLens AI](https://www.canitrustai.company/docs) describes factual-claim verdicts, evidence and an advertised browser extension. [TruthLens](https://www.usetruthlens.com/) describes browser claim checking and per-image confidence badges. [SafePrompt](https://safeprompt.dev/blog/chrome-extension-launch) describes local warnings for hidden-text injection. Their jobs differ from our bounded PS command-risk check, but the combination of browser warnings, badges and evidence is not empty territory. Compact labels alone are not a durable competitive advantage.

**Decision assessment:** competition does not establish that this project is wasted. Independent accuracy, repeat user usefulness and enterprise willingness to adopt remain unproven. Continue building and validating tag by tag, with PS first. Preserve the full scope and keep each release claim behind its own evidence gate. Do not use a claim of uniqueness as the business case.

## Corrections to carry into our positioning

“Tag” is a presentation and evidence contract, not a unique market invention. Other products already use badges, labels, confidence displays and provenance records. A QR link or multiple matching validators does not prove a finding true. Shared methods can share errors. Do not claim that all competitors are unvalidated, or that we are more accurate, without a fair comparison on the same task and independent corpus.

The AI Lab’s implementation licensing is described as TIPCL-1.0 with commercial conditions and a future Apache conversion; its open specification does not establish that its current implementation is unrestricted open source. [Published licensing description](https://theailab.org/insights/announcing-trust-identity-protocol). Likewise, a public GitHub repository, free account or free demo is not itself a complete open-source licensing determination. Check component, model and dataset licenses before integration.

Related use of our name is confirmed on [The AI Lab’s official verification page](https://vp.theailab.org/get-verified). That is a naming risk, not a determination of trademark registration, priority or infringement. Keep legal clearance separate from product benchmarking. No name change or filing is authorized by this inventory.

## Competitive delivery order

Preserve the full scope and expand tag by tag. Do not divert the first release into biometric identity, a global trust score or a broad security platform.

| Outcome | Owner | Completion evidence |
| --- | --- | --- |
| Understandable product | Engineering and product owner | Compact code-only tags; one-sentence job, limitation and visible validation state; accessible keyboard/mobile interactions |
| Accurate bounded PS | Independent reviewers and engineering | Frozen independently labeled holdout, published TP/FP/FN/TN and confidence intervals, calibration evidence, accepted scope and release gates |
| Dependable procedural redaction | Engineering and independent privacy reviewers | Tested ordering, invalid metadata refusal, supported entity/language coverage, failure handling and no claim of complete privacy |
| Open validation path | Engineering and outside users | Anonymous source download, reproducible installation/checks, method/version binding and outside-user trial |
| Safe contribution loop | Engineering, privacy owner and moderators | Accepted consent/retention rules, authenticated isolated intake, deletion/retraction, quotas and synthetic security tests before real collection |
| Credible enterprise product | Engineering and enterprise pilot owner | Working deployment/access/audit boundaries and measured pilot outcomes; personal evidence standard stays intact |

For every accuracy-bearing tag, publish the exact task, supported inputs, method version, dataset provenance and sampling policy, independent labeling procedure, confusion counts, uncertainty, failure/abstention behavior and unresolved limits. Human review has an identified scope; a signature only validates a signature. Development regressions establish regression behavior, not production accuracy. No single aggregate score should conceal a weak tag or subgroup.

The current PS candidate precision and recall gates use Wilson lower bounds, not point estimates. A universal “52 examples means validated” statement is incorrect: denominator, confidence convention, sampling, failures and recall coverage all matter. Our engineering regressions are not the frozen independent holdout. See [PS contract](tags/PS-01.md), [acceptance packet](tags/PS-01-acceptance.md) and [open validation guide](open-validation-path.md).

Before publishing a comparative accuracy claim, freeze the shared task and corpus, use equivalent inputs and thresholds, record unavailable responses separately, preserve raw scores and versions, and disclose costs/data transfer conditions. API access or a vendor’s published benchmark alone cannot support a claim that AI Trust ID wins. For features with different jobs, compare workflow and claim boundaries instead of inventing a shared accuracy ranking.

## Product improvements executed in the first PS validation pass

These are specific tradeoffs, not a claim that competitors are bad or unvalidated.
[TruthLens's own FAQ](https://usetruthlens.com/#faq) says checked page content and
images are forwarded to Anthropic and Hive. Its pricing table lists 15 monthly
page analyses on its free plan. That can be a reasonable product choice; it is a
poor fit for a user requiring no remote inference and no personal per-check cap.
Our personal checker uses local methods without an inference subscription. This
difference has a cost: installation is currently harder, and PS covers a much
narrower job than fact checking or deepfake analysis. Do not imply feature parity.

| Weakness or user requirement | Current improvement | Evidence and remaining gap |
| --- | --- | --- |
| Setup hidden behind a repository link | Every tag modal and static reference now explains use and availability; PS and PII include setup commands | Browser checks cover all 20 records and command copying. General-user one-click install is still missing |
| Broad verdict can be mistaken for a safety clearance | Separate finding, no finding and unavailable explanations; explicit PS boundaries | No supported match cannot clear content as safe. Independent comprehension review remains needed |
| False alarms on file downloads and literal displays | Routing and display corrections, versioned signals and source binding | Five active development sets, 86 cases, zero observed classification errors. Not independent accuracy |
| Predictions recycled as training truth | Blind review preparation with method/policy hashes, empty labels and disagreement visibility | Reviewers and adjudication still needed; automation cannot verify their independence |
| Remote analysis and personal usage metering | No remote inference or per-check API bill in the personal reference checker | Initial software downloads and local compute still cost resources. No comparative privacy/security superiority established |
| Sharp, less approachable typography | Self-hosted Nunito Sans, preserved license and source hashes | Font and layout checked in browser; no external font requests |

Next: accepted sampling and independent labels; an outside-user installation trial;
then a reviewed, simpler installer. Do not substitute a decorative interface or
another development corpus for those checks. Enterprise deployment should retain
these same claim and evidence boundaries.
