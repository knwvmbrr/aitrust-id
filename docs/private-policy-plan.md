# Organization policy boundaries — architecture before implementation

N-010 retains the full personal, team, enterprise and private offering scope. Its
commercial service and namespace adoption remain open. This increment supplies
one complete offline development component: a person deliberately inspects a
caller-selected policy and applies its literal-term rules to a private text file.
It does not activate SSO, host capture, enterprise sales, a public endpoint or an
adopted custom tag namespace.

Keep the public tag method and vocabulary separate. Policy identifiers and result
labels are qualified by an explicitly unverified organization namespace; reject
adopted and proposed public codes as custom codes. No policy field can set public
thresholds, change public meanings, suppress evidence, hide limitations, require
receipts or grant capture/upload permission. Unknown fields refuse the entire
policy. The reference tool never receives or rewrites public assertions. Free
claim labels are not accepted: output wording is fixed to literal occurrence,
with the qualified private code and explicit unverified namespace status.

Use a versioned closed JSON profile, frozen NFC normalization, exact policy/text
fingerprints and bounded case-sensitive whole-phrase matching. Allow at most 32
rules, 8 phrases per rule, 128 code points per phrase and 20,000 input code points.
No arbitrary regular expressions, code, URLs, model downloads or callbacks. A
match means only that a selected literal phrase occurs in the selected text; it
does not establish a violation, intent, authorship, privacy clearance or truth.
Bounded output may be explicitly marked truncated; invalid input never returns
partial observations. Explicit local invocation is required after reviewing the
policy. That is a tool-control signal, not proof of employee consent or an
organization's right to impose a rule.

Read only fixed owner-private, regular, singly linked files outside the source
checkout, using the established descriptor-bound reader. No automatic storage,
registry, upload, telemetry or training. Keep console output brief and free of
source text, custom labels, fingerprints and raw locations. Optional detailed
JSON is a separate explicit save to a new private folder; fingerprints and
locations can still link information. There is no HTML renderer or template
execution. A caller can stop using this optional tool without disabling personal
checks. Compromised same-account processes or administrators remain out of scope.

Tests must exercise actual CLI invocation, positive/negative phrase boundaries,
multiple distinct policy namespaces, frozen Unicode locations, complete malformed
profile refusal, public-code collisions, attempted public-policy weakening,
unsafe file access, oversized inputs and no overwrite. Demonstrate unchanged
public methods before/after an invented private-policy run and repeat selected
controls in isolated Linux. Keep full N-010 acceptance open until namespaces,
ownership, each organization workflow and privacy/human operation are accepted.
